/about

Opengrep is a SAST (static application security testing) engine. It finds vulnerabilities by analyzing source code without executing it. It checks the code against a set of rules. A rule can match a code pattern, or track untrusted data as it flows through the program, for example from an HTTP request into a SQL query.

## analysis

  • semantic & type-aware matching

    Rules are written as code and matched against the syntax tree, so formatting and comments don't matter. Names are resolved too, so a function imported under another name still matches. Matching can also use type information that Opengrep infers during analysis, for example to flag stmt.execute(query) only when stmt is a database Statement, and not a thread pool that has an execute method too.

  • constant & symbolic propagation

    Values and expressions are tracked through assignments: a rule for shell=True also matches shell=flag when flag is True.

  • taint analysis

    Declare where untrusted data comes from (sources), where it must not end up (sinks) and what makes it safe (sanitizers). Opengrep flags unsanitized flows from sources to sinks.

  • field sensitivity

    Taint is tracked per field: a tainted user.name doesn't make user.id tainted.

  • cross-function & cross-file taint

    With --taint-intrafile, Opengrep summarises how each function passes tainted data along, and follows it through calls, return values, lambdas and higher-order functions like map. For a whole project, --taint-interfile builds a call graph and follows data from a source in one file to a sink in another, for example from a request handler to a SQL query in a separate data-access module. Taint is also tracked through standard library functions and classes, so user input stored in a list or map and read back later is still tainted.

## tools

  • playground

    A desktop app for writing rules: edit a rule next to sample code, run it and see what it matches, and run the rule's tests. For Linux, macOS and Windows, from opengrep/opengrep-playground.

  • agent skill

    Teaches AI coding agents such as Claude Code, Codex and OpenCode to use Opengrep: to write new rules, scan for vulnerabilities, and find code by its structure where grep falls short. Install it with npx skills add opengrep/skills, or get it from opengrep/skills.

## ci & integrations

  • ci mode

    opengrep ci reports only the findings a pull request introduces, and --baseline-commit compares against any commit. opengrep install-ci sets up GitHub Actions.

  • output formats: SARIF, JSON & more

    SARIF, JSON, JUnit XML, GitLab SAST and GitLab Secrets, plus Emacs and Vim formats. Several at once from a single run.

  • fingerprints

    Every finding in JSON and SARIF carries a fingerprint built from the rule, the file path and the matched code, not line numbers, so findings can be tracked across commits as code moves.

  • autofix

    Rules can carry a fix that replaces vulnerable code with a safe equivalent, for example el.innerHTML = comment with el.textContent = comment. Use the --autofix flag to apply fixes in place, and --dryrun to preview them without touching files.

  • editor integration

    opengrep lsp runs a language server for your editor.

## performance

  • multicore engine

    OCaml 5 with shared-memory parallelism across all cores.

  • dynamic timeouts

    Timeouts scale with file size (--dynamic-timeout), and rules can set their own.

  • resource limits

    Caps on memory and file size, and an option to skip minified files.

  • native binaries

    Self-contained and Cosign-signed, for Linux, macOS and Windows.
