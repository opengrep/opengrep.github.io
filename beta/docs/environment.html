Environment variables

This section describes the environment variables that Opengrep reads.

## OPENGREP_ and SEMGREP_ names

For compatibility, most variables whose names start with OPENGREP_ can also be set with the prefix SEMGREP_: SEMGREP_TIMEOUT is read as OPENGREP_TIMEOUT. When both are set, the OPENGREP_ variable takes precedence. The entry of such a variable lists its SEMGREP_ name as an alias. Some variables, such as OPENGREP_SKIN, are read only under their OPENGREP_ name, and variables such as NO_COLOR have neither prefix.

A variable set to the empty string is treated as unset.

## Variables and flags

Some variables set the same value as a command-line flag, shown in the Equivalent flag column. When both are given, the flag takes precedence, and Opengrep logs a warning:

[00.04][WARNING]: --timeout is given; ignoring $OPENGREP_TIMEOUT

An invalid value of a variable is reported in the same way as an invalid flag value, and Opengrep exits with status 2.

## Examples

### An empty value is treated as unset

In this example, OPENGREP_RULES is empty, so Opengrep takes the rules from --config and logs no warning about the variable.

rule.yaml
rules:  - id: find-eval    pattern: eval(...)    message: found eval    languages: [python]    severity: WARNING
app.py
eval(1)
Command and result
$ OPENGREP_RULES="" opengrep scan --config rule.yaml app.py 2>&1 | grep -c WARNING
0
