reference / Commands

opengrep ci

See also
opengrep scan, --audit-on, --suppress-errors, --subdir, --baseline-commit, opengrep install-ci, --error, OPENGREP_PR_ID, OPENGREP_REPO_NAME
opengrep ci [FLAGS]

Runs the same engine as opengrep scan, with the defaults a CI job wants. It takes no target arguments: it scans the current directory, or the directory given by --subdir, and it expects to be run from the root of a git repository. Elsewhere it warns and carries on with whatever it can work out.

Rules come from --config or OPENGREP_RULES, as for a scan. With neither, ci falls back to --config auto and fetches rules from the registry.

What ci adds to a scan:

  • Repository metadata. It works out the CI provider from the environment (GitHub Actions, GitLab CI, CircleCI, Jenkins, Bitbucket, Azure Pipelines, Buildkite, Travis; otherwise plain git). The first line it prints on standard error names the provider and the event that triggered the run, such as git · unknown or gitlab-ci · push. Variables such as OPENGREP_PR_ID can set parts of the metadata; see Environment variables.
  • A baseline. The baseline comes from that metadata, so in a pull or merge request only findings that the request introduces are reported. --baseline-commit overrides it.
  • Blocking findings. A finding is blocking or not according to its rule's metadata. ci lists the rules of the blocking ones under blocking rules fired and exits 1 when there is at least one, without needing --error. --audit-on turns that status back into 0 for a given CI event.
  • Suppressed errors. By default any other failure becomes exit status 0, so a broken rule file does not fail the build. See --suppress-errors.

## Exit status

StatusMeaning
0The scan ran and no blocking finding was reported.
1At least one blocking finding was reported.
otherThe codes of opengrep scan, but only with --no-suppress-errors; otherwise they become 0.

## Flags

FlagSummary
--allow-local-buildsLet opengrep build the project to work out its dependencies; it has nothing to act on in opengrep.
--allow-rule-timeout-controlLet rules set their own time limits, which opengrep otherwise ignores.
--audit-onReport blocking findings but exit 0 when the CI event has one of these names.
--baseline-commitReport only the findings that are not already present in the given commit.
--configLoad rules from a file, a directory, a URL, a git repository or the Semgrep registry.
--dataflow-tracesShow how a value reaches the finding, for taint rules.
--debugLog everything --verbose does and the engine's own diagnostics as well.
--developListed in Internal and debugging interfaces.
--disable-interfileKeep every taint rule within single files, even rules that ask to follow taint across files.
--disable-intrafileKeep every taint rule within single functions, even rules that ask to follow calls.
--dynamic-timeoutScale each rule's time limit with the size of the file being scanned.
--dynamic-timeout-max-multiplierThe ceiling on how much a file's size may stretch the timeout.
--dynamic-timeout-unit-kbThe file size, in KB, that counts as one step when scaling the timeout.
--emacsPrint one line per finding, in the form Emacs compilation buffers parse.
--emacs-outputAlso write the findings in Emacs single-line format to a file.
--enable-nosemWhether a nosem comment silences findings on its line; on by default.
--enable-version-checkAccepted for compatibility; opengrep never checks for a newer version.
--excludeSkip files and directories whose path matches a gitignore-style pattern.
--exclude-ruleSkip a rule by its id, whichever config it came from.
--experimentalAccepted for compatibility; opengrep has only the one implementation.
--files-with-matchesPrint only the paths of the files that have findings.
--force-colorStyle the output even when it is not going to a terminal.
--force-excludeApply --include and --exclude to files named on the command line as well.
--gitlab-sastPrint the findings as a GitLab SAST report.
--gitlab-sast-outputAlso write the findings as a GitLab SAST report to a file.
--gitlab-secretsPrint the findings as a GitLab secret detection report.
--gitlab-secrets-outputAlso write the findings as a GitLab secret detection report to a file.
--includeScan only the files whose path matches one of these patterns.
--inline-metavariablesReplace metavariables in a rule's metadata with what they matched.
--interfile-dedup-byWhether a sink that several sources reach across files is one finding or one per source.
--interfile-timeoutTime a rule may spend on the cross-file analysis.
--jobsHow many cores run rules in parallel.
--jsonPrint the findings as a JSON document instead of the text report.
--json-outputAlso write the findings as JSON to a file.
--junit-xmlPrint the findings as a JUnit XML report, so a CI system shows them as failed tests.
--junit-xml-outputAlso write the findings as a JUnit XML report to a file.
--matching-explanationsAdd to the JSON output a trace of how each part of a rule matched.
--max-chars-per-lineWidth at which a finding's code lines are wrapped in the text report.
--max-lines-per-findingHow many lines of code a finding may show before the rest is trimmed.
--max-log-list-entriesHow many items a list in the logs may show before it is replaced by a note.
--max-match-per-fileHow many findings one file may have, across all rules, before they are all dropped.
--max-memoryMemory a single file's analysis may use before it is abandoned.
--max-target-bytesSkip files larger than this when walking a directory.
--opengrep-ignore-patternRecognise one more comment prefix that silences findings on a line.
--optimizationsTurn the engine's optimizations, chiefly the prefilter, on or off.
--outputWrite the findings to a file instead of standard output.
--profileListed in Internal and debugging interfaces.
--quietPrint the findings and nothing else.
--rewrite-rule-idsWhether a rule loaded from a directory gets its path as a prefix; on by default.
--sarifPrint the findings as a SARIF 2.1.0 document.
--sarif-outputAlso write the findings as SARIF to a file, suppressed findings included.
--scan-unknown-extensionsScan a file named on the command line even when its extension names no language.
--skinWhich layout the text report uses.
--subdirScan only this directory, while the repository still provides the CI metadata.
--suppress-errorsWhether an error fails opengrep ci; on by default, so errors exit 0.
--taint-interfileFollow taint across files, for every taint rule.
--taint-interfile-depthHow many calls deep the cross-file taint analysis follows a chain.
--taint-intrafileFollow taint through calls to functions defined in the same file, for every taint rule.
--textPrint the human-readable report, which is what a scan does anyway.
--text-outputAlso write the text report to a file.
--timeReport how long the scan took, per rule and per file.
--timeoutMaximum time in seconds for one rule on one file; 0 means no limit.
--timeout-thresholdHow many rules may time out on a file before opengrep gives up on that file.
--use-git-ignoreWhether .gitignore decides which files are scanned; on by default.
--verboseLog what the scan is doing, at the info level.
--vimPrint one line per finding, in the form Vim quickfix lists parse.
--vim-outputAlso write the findings in Vim quickfix format to a file.

## Examples

### A scan of a repository

rule.yaml
rules:  - id: find-eval    pattern: eval(...)    message: found eval    languages: [python]    severity: WARNING
app.py
eval(1)
Command and result
$ git init -q && git add . && git commit -qm init
$ opengrep ci --config rule.yaml
blocking · 1 finding

app.py

  warn  find-eval
  found eval

    1 │ eval(1)

blocking rules fired
  find-eval
$ opengrep ci --config rule.yaml > /dev/null 2>&1; echo "exit status: $?"
exit status: 1

The line naming the provider and the event, the counts and the closing summary go to standard error:

Command and result
$ opengrep ci --config rule.yaml 2>&1 >/dev/null | tail -3
CI scan completed successfully.
  Found 1 finding (1 blocking) from 1 rule.
  Has findings for blocking rules so exiting with code 1
