reference > Rule syntax

metadata

See also
--inline-metavariables, --sarif, --json, --gitlab-sast

A mapping of arbitrary keys and values attached to the rule. Opengrep does not interpret it when matching. Each finding in the JSON output contains the metadata of its rule unchanged, in extra.metadata.

The SARIF and GitLab SAST outputs read some keys:

KeyValueUse
cwea string or a list of stringsSARIF: each entry becomes a tag of the rule, and the tag security is added.
owaspa string or a list of stringsSARIF: each entry becomes a tag, prefixed with OWASP-.
confidencea string, such as HIGH or LOWSARIF: the tag <value> CONFIDENCE. GitLab SAST: the confidence detail; LOW also flags the finding as a likely false positive.
tagsa list of stringsSARIF: added to the tags of the rule.
referencesa URL or a list of URLsSARIF: listed under References in the help of the rule.
sourcea URLSARIF: the helpUri of the rule, also listed under References. GitLab SAST: the URL of the identifier.
shortDescriptiona stringSARIF: the short description of the rule, Opengrep Finding: <id> by default.
helpa stringSARIF: the help text of the rule, the message by default.
security-severitya numberSARIF: the security-severity property of the rule.
shortlinka URLThe legacy skin of the text output prints it below the message, as Details:.

With --inline-metavariables, metavariables in string values of the metadata are replaced by the code they matched.

## Examples

### Metadata in the JSON output

rule.yaml
rules:  - id: sql-injection    pattern: cursor.execute("..." % ...)    message: SQL query built with string formatting    languages: [python]    severity: ERROR    metadata:      cwe:        - "CWE-89: Improper Neutralization of Special Elements used in an SQL Command ('SQL Injection')"      owasp:        - "A03:2021 - Injection"      confidence: HIGH      references:        - https://owasp.org/Top10/A03_2021-Injection/
app.py
cursor.execute("SELECT * FROM users WHERE name = '%s'" % name)
